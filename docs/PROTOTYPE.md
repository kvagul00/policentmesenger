# Полицентр Workspace — мессенджер, прототип 1

Интерактивный прототип: каналы команды, чаты заказов, текстовые сообщения, ответы, реакции, локальные вложения, поиск, карточки и этапы заказов, список заказов, создание чатов, экспорт истории.

## Важная граница версии

Данные хранятся в localStorage браузера, синхронизируются между вкладками одного origin. Серверной переписки между сотрудниками, входа, надёжного контроля ролей и общей базы здесь пока нет. Роли в настройках — только демонстрация интерфейса. Демонстрационные участники не являются подключёнными сотрудниками. Ограничение файла — 1 МБ, суммарно 2 МБ / 3 файла в сообщении. Из-за квоты localStorage для постоянной работы нужен сервер.

Ни одной записи MDB в приложение не загружено. Файл MDB не меняется.

## Следующий этап: рабочий многопользовательский MVP

1. Вход сотрудников и серверные роли manager/executor; назначение исполнителей.
2. PostgreSQL: users, channels, channel_members, messages, message_attachments, message_reactions, orders, order_assignments, order_stage_events, payment_events, audit_events.
3. API с серверной проверкой ролей и membership, пагинация сообщений; WebSocket/SSE с возобновлением по event_id.
4. Объектное хранилище вложений, ограничения доступа и резервные копии.
5. Перенос согласованных сценариев прототипа в серверную версию.
6. Адаптеры Access/Excel → staging → проверка → заказы; стабильные UUID сохраняют связь с чатами. Импорт не меняет сообщения и этапы производства.

Статус оплаты виден сотрудникам, подтверждается менеджером; исходное состояние unknown. Финансовые суммы в производственных чатах не показывать. Имена и роли нельзя принимать от клиента как основание доступа.

## Запуск и проверка

Нужен Node.js. Из каталога проекта:
- node preview.cjs — локальный HTTP-сервер, адрес печатается при запуске.
- node --test domain.test.mjs — проверки правил переходов и валидации сообщений.

dist/ — buildless HTML/CSS/JS. .openai/hosting.json — идентификатор частного Sites-проекта.
